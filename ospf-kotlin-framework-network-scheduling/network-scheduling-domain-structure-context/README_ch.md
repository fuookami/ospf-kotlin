# 网络结构

[English](README.md) | [框架说明](../README_ch.md)

公共接口：`NetworkStructureProblem<V> / NetworkStructureContext<V>`。不可变问题持有 `NetworkDesignProblem<V>`；每个 context 根据传入的数值适配器创建独立的 `NetworkDesignContext<V>`。

上下文在显式允许的根节点、终端和可选 Steiner 中转节点上构建根有向树。每个激活的非根节点恰有一条入选父弧，根节点没有父弧；有界深度约束显式排除有向环，深度上界为允许树节点数减一，因此无环联动常数有限且由图规模导出。终端必须连接，中转节点可选。弧使用 `NetworkArcId` 标识，因此平行弧各自独立选择；自环固定关闭。模型严格沿用弧方向，不会反向或根据成本猜测树形，连通性不依赖低成本树假设。

树弧联动到建设上下文中对应的服务可用性，以及弧两端的设施启用状态；树中激活的候选设施必须开设。未配置可选建设决策的设施/服务按既有可用处理。设施分区请求显式列出合格设施，默认要求恰好归属一个设施，也可允许未覆盖；另可配置每个设施的分区数量配额。归属是独立的二元覆盖决策，不从商品流需求推导，也不与流量混为一体。

注册时只复用建设组件（设施/服务变量与预算），刻意不注册名义商品流。默认会通过独立的目标 pipeline 最小化 `constructionCost`；嵌入到由外部统一组合目标的模型时传入 `minimizeCost = false`，费用表达式仍然开放给调用方。未知/重复引用与无效配额边界会在注册校验时返回问题错误；但有效图中的终端断联、必需分区没有合格设施、最小配额超过可覆盖数量都会保留为模型约束，由求解器报告模型不可行，不作为注册失败。建设领域值仍使用 `V : RealNumber<V>` 与 `Quantity<V>`，只在设计适配器边界进入 solver `Flt64`。context 只能使用一次；注册失败后丢弃 context 和部分修改的模型。本模块不依赖原生求解器测试或 application。
