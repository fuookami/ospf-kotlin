# ospf-kotlin 1.1.2

:us: English | :cn: [简体中文](1.1.2_ch.md) | [README](../README.md)

This release covers changes starting at commit
`85d7221e433ba9793a4462b32e7fda6fbd5b396a` (inclusive), through
`9d56344fef571ac4eb17e0a5832bdcfa26a15dbb`. All Maven modules and current
README dependency examples are aligned to 1.1.2; earlier release notes retain
their historical versions.

## Summary

1.1.2 adds reusable 1D/2D packing and 2D cutting-stock frameworks, shared
unit-aware geometry and discrete loading, broader standalone network optimization,
finite-domain activity scheduling with temporal inventory, and a configurable
hyper-heuristic search framework. Shared decomposition now supports linear Benders
and revision-checked dynamic-row/column projection. This release includes breaking
heuristic and network API changes; review the migration notes before upgrading.

## Physical Units and Mathematical Foundations

- Physical-unit multiplication, division and powers now compose the units' own
  value domains rather than losing overrides to quantity defaults. Powers derive
  dimensions, scale and domain independently, preserving discrete positive powers.
- Added shared `productUnit`/`quotientUnit` composition and corrected dimension-power
  accumulation for geometry calculations such as length multiplied by length.
- Added reusable Gaussian, Cauchy, Levy, exponential, Gamma, Beta, Student-t,
  truncated, uniform and direction distributions, fractal escape-time/dimension
  helpers, and `ChannelProjection` for scalar channels from multi-component sequences.
- Chaotic mappings accept caller-provided random generators. `WindmiAttractor`
  uses a generic floating-point model; `RealNumber.isFinite` no longer accepts NaN.

## Packing, Cutting Stock and Shared Geometry

- Added solver-independent `ospf-kotlin-framework-geometry2d` for quantity arithmetic,
  points/vectors, rectangle/circle shapes, placements, sheet boundaries, internal
  overlap and kerf spacing. Boundary contact is not treated as overlap.
- BPP1D now has seven modules covering infrastructure, item definitions, pattern
  generation/assignment, discrete loading, packing and application orchestration.
  MILP and column generation support FFD/BFD seeds, pricing, mixed bin types,
  finite stock, exact demand, tail-bin repacking, CSV input, KPIs and rendering.
- BPP2D now provides modular rectangle/circle packing, block/BLA/grid candidates,
  restricted-master column generation with reduced-cost filtering, final MILP,
  tail-sheet optimization, kerf-aware spacing, independent geometry checks,
  remnant reporting and validated CSV datasets.
- BPP2D and BPP3D generate candidates across multiple sheet/bin types. Default
  mixed-type objectives prioritize consumed area/volume, with small count
  tie-breakers and optional type-cost weights; column identities include type.
- CSP2D now has eight modules for fixed sheets and coils, rectangular products,
  demand/capacity/yield/waste modeling, sheet assignment and application solving.
  Freeform, two-stage guillotine and three-stage guillotine patterns retain their
  manufacturing semantics and validated cut trees. Same-direction parallel cuts
  remain in the same stage; changing direction advances the stage.
- CSP2D exposes MILP and iterative candidate-pool solving. Candidate augmentation
  is driven by remaining demand, not a complete dual-driven pricing oracle.
  Irregular/circular cutting parts and cross-order remnant inventory are not included.
- Corrected circular hex-grid pitch scaling with diameter, rotation permission
  checks, shelf-row kerf accounting and `maxCandidates` output-count semantics.
- CSP1D now uses a separate artificial-shortage feasibility phase when initial
  columns cannot satisfy the restricted master, then rebuilds the original master.
  Existing columns do not consume the new-column budget. LP dual use requires a
  valid optimal solution; final MILP extraction rejects missing incumbents.

## Shared Discrete Loading and Linear Decomposition

- Added `ospf-kotlin-framework-bpp` with sparse legal cargo-position assignments,
  whole-position occupancy, count/weight capacities, explicit layout groups and
  non-transitive geometric conflicts. BPP1D/BPP2D supply separate geometry adapters.
- Added independent partition-configuration column generation over complete,
  explicitly owned partition configurations. Business rows and resource decisions
  participate in master assembly and pricing, not only final-result validation.
- Added reusable `LinearBendersAlgorithm` with master/continuous-recourse partitioning,
  validated optimality/Farkas cuts, stable bindings, cut deduplication and independent
  full-model verification. Gurobi infeasible-subproblem extraction is corrected;
  fallback reconstructs a fresh full model instead of reusing failed state.
- Added model-owned linear snapshots, stable row IDs and structural revisions.
  `ColumnProjection` shares column mapping, master construction, linear pricing,
  dual projection and solution merging outside the BPP domain.
- Dynamic row/objective/bound changes invalidate stale registrations and pricing
  requests. Duals bind to actual constraint objects and require complete finite
  values; all blocks price against one snapshot before batch column insertion.
- Restricted integer-pool success is not a global integer-optimality certificate.
  Partition CG and Benders remain separate strategies, not a combined algorithm.

## Network Optimization and Gantt Integration

- Added immutable directed multigraphs with stable node/arc IDs, parallel arcs,
  topology queries and solver-independent finite resource-state path search.
  VRPTW pricing and Gantt network subproblems reuse the shared path kernel.
- Separated immutable `FlowProblem` input from per-model `FlowContext` registration.
  Standalone contexts/application services cover multi-commodity flow, facility and
  service design, capacity levels, budgets and explicit-scenario resilience.
- Added allocation with compatibility, quotas, transshipment and optional hubs;
  whole-path binary selection; rooted/Steiner structures and facility ownership;
  generalized flow with loss/yield and explicit single-input conversion.
- Column addition/removal, objective refresh, extension-row coefficients and pricing
  duals now share lifecycle/scope checks. Removed candidate-pool pseudo lower bounds
  and distinguish heuristic progress from certified no-improvement evidence.
- Added the optional Gantt network context and `ospf-kotlin-starter-gantt-network`.
  Network owns reusable graph/flow/path components; Gantt retains global task,
  executor, calendar and space-time orchestration ownership.

## Finite-Domain Activity Scheduling and Inventory

- Added activity contexts, aggregations, components and pipelines plus the standalone
  `ActivitySchedulingApplicationService`, reusing existing MILP solver interfaces.
- Activities support alternative modes and finite allowed starts, phased simultaneous
  equipment/personnel/tool use, capacity calendars, Start/Finish dependency endpoints
  with min/max lags, baseline freezing/change costs and explicit execution facts.
- Added unit-aware temporal inventory with opening stock, fixed and activity-relative
  material events, hard lower/storage bounds, explicit whole-order cancellation,
  inventory traces and independent result validation. Simultaneous events settle
  atomically; future receipts cannot cover earlier shortages.
- Optimality applies only to the declared finite candidate model. Automatic
  preemption, general BOM/MRP, partial shortage fulfillment and a complete APS
  product are not claimed by this increment.

## Heuristic and Hyper-Heuristic Search

- Moved heuristic implementations out of core into
  `ospf-kotlin-core-plugin-heuristic`. Shared lifecycle skeletons and replaceable
  operator families replace algorithm-private loops, with composed single-objective,
  Pareto NSGA-II/III, island and memetic solvers.
- Added persistent stepwise sessions, two-level algorithm/operator selection,
  shared evaluation budgets, random streams, archives, synchronous/asynchronous
  scheduling, exchange memory, training, replay, registries and versioned recovery.
- Added DSL/JSON/YAML/TOML configuration, strategy snapshots and checkpoint/local
  persistence. TOML uses the standard tomlj parser with floating-point/negative-zero
  preservation, finite-value/null checks and UTF-8 size limits.
- Added FRR-MAB, Choice Function, Adaptive Pursuit and tabular Q-learning policies;
  Pattern Search, VND, elite local search and permutation destroy/repair operators;
  Late Acceptance, Record-to-Record and parameter-free `AutoAcceptance`.
- Constraint-aware ordering integrates feasibility-first, epsilon and stochastic
  ranking without replacing business objectives. Rewards include normalized time,
  dominance and multi-dimensional hypervolume with explicit exact/sampled modes,
  reproducibility, resource limits and uncertainty diagnostics.
- SHADE/L-SHADE and CMA-ES offer an explicit shared numerical contract for Rust
  interoperability. Versioned asynchronous schedule logs support real-execution
  replay, quiescent checkpoint prefixes and validated atomic storage.
- Fixed strict objective comparison, Q-learning state/action behavior, probability
  floors, asynchronous terminal credit, element conservation and regret overflow.
  Failure/stop recovery preserves valid candidates, random/learning state and actual
  evaluation charges, merging in-flight work exactly once.

## Tests and Documentation

- Added contract/regression coverage for unit domains, geometry, packing/cutting,
  decomposition certificates, dynamic rows, network lifecycle, activity inventory,
  heuristic numerical vectors, asynchronous replay and failure recovery.
- Added opt-in Gurobi/SCIP integration suites and updated Demo2/Demo4/Demo5 paths.
  Native libraries/licenses remain external prerequisites; skipped tests are not
  evidence of native-backend acceptance.
- Updated module/starter documentation and dependencies. Root README module tables
  now include shared BPP and geometry modules and reflect implemented framework scope.
- The SCIP CP runtime plugin-version fallback is aligned to 1.1.2, keeping provenance
  and runtime fingerprints consistent when package version metadata is unavailable.
- Test-suite additions listed here describe release content, not a claim that every
  optional profile or external service was rerun during version preparation.

## Migration Notes

- Update all downstream OSPF Maven dependencies/BOMs to 1.1.2. Third-party SDK/parser
  versions are independent and are not changed by this release-version alignment.
- Heuristic consumers must add the heuristic plugin artifact; core alone no longer
  supplies those implementations. Replace legacy `GAPolicy`, `PSOPolicy`,
  `ParticleSwarmHeuristicSolver` and old GA/PSO entry classes with composed factories
  or facades such as `islandGenetic`/`particleSwarm` and `StoppingCriterion`.
  `AbstractRunner.run` returns `Ret<List<Individual<O, V>>>`; handle failures explicitly.
- Network consumers must use `NetworkGraph<N, A>` with explicit payload types and
  stable arc IDs, and replace `FlowGraph` usage with `FlowProblem`/`FlowContext`.
  Create fresh registration state per model and use shared path/pricing contracts.
- Import shared 2D geometry from `fuookami.ospf.kotlin.framework.geometry2d`; the
  common placement type is `Placement2`. Review mixed-bin default objective weights
  if existing applications intentionally optimized count instead of area/volume.
- Honor pricing completion/scope and solver terminal status before claiming bounds
  or optimality. Recreate pricing requests after structural changes and register
  downstream rules through contexts/pipelines so their coefficients enter pricing.
- SCIP runtime fingerprints include the plugin version. Checkpoints from another
  plugin version are not automatically interchangeable; retain fingerprint validation.
