# ospf-kotlin 1.1.1

:us: English | :cn: [简体中文](1.1.1_ch.md) | [README](../README.md)

This release is based on the 1.1.0 release baseline at commit
4ee4a5ed628959a2af6d865ff0580cfb52307e9f. The post-release change range starts at
695e66ecea212b7c1ce3d07e3ba9f26f89d81d6a and is included through
224b35628d02b3d8a47acd6b3d574186186ce15e.

## Summary

1.1.1 extends the optimization core with a critical-constraint analysis pipeline, aligns
function-symbol registration and quadratic modeling behavior, synchronizes the remote solver
protocol client, and refreshes the Kotlin/JVM build toolchain. All Maven modules are versioned
as 1.1.1.

## Core symbols and model lifecycle

- Dedicated function-symbol contract tests now cover logical, range, masking, piecewise, slack,
  aggregation, trigonometric, rounding, and quadratic symbols.
- Generic registration tests exercise Flt64, FltX, Rtn64, and RtnX paths for linear and
  quadratic functions. Registration behavior now distinguishes expression-only functions from
  functions that must append solver constraints.
- Strict zero-band and nonzero-boundary handling was tightened for logical and ternaryization
  functions, including validation of tolerance and strict-boundary configuration.
- Range, indicator, masking, piecewise, slack, and quadratic symbol implementations were
  synchronized. New quadratic positive-part, absolute-slack, and range-slack symbols provide
  exact helper models for quadratic expressions.
- Intermediate model ownership was corrected: closing a derived dual or elastic model no longer
  closes and empties the source model. Constraint-programming lowering now keeps explicit source
  provenance and stable identity rules for generated rows and variables.
- Constraint-programming event evaluation now aggregates changes occurring at the same time before
  checking cumulative bounds.

## Critical constraint analysis

- Added the core.analysis API for diagnosing critical or blocking constraints against an
  immutable constraint-programming snapshot and an optional baseline solution.
- CriticalConstraintAnalysisSession and CriticalConstraintAnalysisPipeline coordinate
  capability detection, diagnostic activation, cache reuse, status propagation, and report
  assembly.
- The analysis surface includes constraint activity, target feasibility, conflict extraction and
  deletion verification, RHS/removal perturbation, fixed-integer LP sensitivity, criticality
  profiles, candidate ranking, and correction recommendations.
- Reports preserve evidence provenance and distinguish reachable, unknown, unsupported, and
  failed conclusions. Correction helpers can produce minimal or weighted correction sets and
  alternative improvement plans without treating unproven results as facts.
- Fixed-integer LP analysis maps duals and native RHS ranges back to original constraint IDs
  only when the lowering provenance is unique. SCIP and Gurobi adapters and integration tests
  cover the backend boundary.

## Solver adapter native functions

- Added solver-adapter capability detection and lowering planning for native function support,
  including usage context, solver version, objective/constraint placement, and safe fallback.
- Gurobi 10/11、COPT 8、CPLEX 12 和 SCIP 9 now share native piecewise-writer
  dispatch while preserving their SDK-specific writers and failure injection boundaries.
- Native ABS, MAX, indicator, masking, binary-logic, semi-continuous, and piecewise paths
  retain deferred structures, fallback constraint regions, stable report recovery, and atomic
  materialization semantics. Unsupported or failed native lowering returns to the intermediate
  model expansion path without losing provenance.
- Added a reusable `NativeFunctionWriterRegistry` so solver adapters can register ordered,
  typed writers without hard-coding one dispatch branch per function symbol.

## Quadratic function symbols

- Added the shared `FunctionSymbolLifecycle` and public quadratic registration contract while
  keeping linear and quadratic constraint registration type-safe.
- Added quadratic counterparts for MAX, ABS, MIN-MAX, MAX-MIN, masking, IF, IF-IN, IF-THEN,
  and inequality satisfaction. They can be registered in `QuadraticMetaModel` and referenced
  by quadratic objectives or constraints.
- Quadratic compositions bind each genuinely quadratic input to a bounded helper variable with
  an exact quadratic equality; affine inputs do not add bridge variables. This avoids accidental
  cubic or quartic expansion, but may produce non-convex MIQCP models.
- Quadratic function registration validates finite bounds, preserves nested dependencies, and
  rolls back partial constraint writes on failure. No quadratic approximation policy was added
  for PWL/SOS or trigonometric/sigmoid functions.

## Remote solver protocol

- The Kotlin remote solver client is aligned with the current task protocol, including capability
  probing, task submission and lookup, stop/resume actions, API envelopes, structured error
  mapping, and transport abstractions.
- Scheduling and execution models now carry task budgets, deadlines, estimates, quality targets,
  preemption and resume modes, slice outcomes, queue information, fingerprints, diagnostics,
  checkpoint references, incumbent references, exact integer objectives, and proof/status
  semantics.
- Added portable checkpoint v2 models and a codec with model fingerprints, integrity SHA-256,
  incumbent/conflict/Benders state, and explicit migration support for recognized legacy v1
  snapshots.
- Remote report mapping and slice orchestration retain checkpoint state and the additional
  scheduling/result fields. Unknown remote enum values are mapped conservatively and are never
  treated as successful proof or termination states.

## Tests and validation

- Added dedicated function-symbol contract coverage and generic registration/regression tests.
- Added analysis fixture, protocol, session, activity, conflict, perturbation, target, report,
  recommendation, and capability tests.
- Added SCIP and Gurobi critical-constraint integration tests using common hand-checkable models.
- Expanded remote solver HTTP tests with capability, scheduling, checkpoint, exact-objective,
  status, diagnostics, and compatibility fixtures.
- Updated example and framework tests for the synchronized symbol and protocol behavior.

## Build and dependency updates

- Kotlin is upgraded to 2.4.20, with the primary JVM and Java compiler target set to JDK 25.
- The documented baseline is now JDK 25+, while the existing JDK 8+ compatibility/packaging
  branch requirement remains documented.
- Maven Compiler Plugin is upgraded to 3.14.1; Surefire and Failsafe are upgraded to 3.6.0.
- kotlinx dependencies are aligned to datetime 0.8.0, coroutines 1.11.0, and serialization
  1.11.0.
- Log4j is upgraded to 2.26.1, Log4j API Kotlin to 1.5.0, SLF4J API to 2.0.19, Jackson
  to 2.22.2, and Ktorm to 4.2.1.
- Maven coordinates throughout the multi-module build are updated from 1.1.0 to 1.1.1.

## Migration notes

- Update downstream Maven dependencies to 1.1.1.
- Consumers of the analysis API should inspect the returned analysis status and evidence before
  applying a correction; Unknown and Unsupported are intentional outcomes.
- Remote solver deployments should advertise the supported protocol/model capabilities before
  submitting checkpointed or scheduled tasks.
- For the broader 1.0.x to 1.1.0 API migration, see the [1.1.0 changelog](1.1.0.md).
