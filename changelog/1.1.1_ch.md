## 总览

1.1.1 为优化 core 增加了关键约束分析管线，统一了函数符号注册和二次建模行为，
同步了 remote-solver 协议客户端，并刷新了 Kotlin/JVM 构建工具链。所有 Maven 模块
的版本统一为 1.1.1。

## Core 符号与模型生命周期

- 新增函数符号专用契约测试，覆盖逻辑、区间、掩码、分段、松弛、聚合、三角函数、
  舍入和二次函数等符号。
- 通用注册测试覆盖 Flt64、FltX、Rtn64 和 RtnX，验证线性与二次函数路径。
  注册行为现在能区分仅表达式函数，以及必须向求解模型追加约束的函数。
- 收紧逻辑函数和三值化函数对零容差、非零严格边界的处理，并校验容差和严格边界
  的配置关系。
- 同步区间、指示变量、掩码、分段、松弛和二次符号实现。新增二次正部、二次绝对
  松弛和二次区间松弛符号，为二次表达式提供精确的辅助建模。
- 修正中间模型的资源所有权：关闭派生的对偶模型或弹性模型时，不再误关闭并清空
  来源模型。约束规划降阶过程现在保留显式来源 provenance，并正确处理生成行和变量
  的稳定身份规则。
- 约束规划中的事件求值现在会先聚合相同时间发生的变化，再检查 cumulative 边界。

## 关键约束分析

- 新增 core.analysis API，用于针对不可变约束规划快照和可选基线解分析关键约束
  或阻塞约束。
- CriticalConstraintAnalysisSession 和 CriticalConstraintAnalysisPipeline 负责
  能力识别、诊断激活、缓存复用、状态传播和报告组装。
- 分析能力包括约束活动性、目标可达性、冲突提取与删除复验、RHS/删除扰动、固定整数
  LP 敏感性、关键性画像、候选排序和修正建议。
- 报告保留证据来源，并区分可达、未知、不支持和失败结论。修正辅助函数可以生成
  最小或加权修正集以及替代改进方案，不会把未经证明的结果当作事实。
- 固定整数 LP 分析只有在降阶 provenance 唯一时，才会把对偶值和后端原生 RHS
  范围映射回原始约束 ID。SCIP 和 Gurobi 适配器及集成测试覆盖了这一后端边界。

## Remote solver 协议

- Kotlin remote solver 客户端已与当前任务协议对齐，支持能力探测、任务提交与查询、
  停止/恢复操作、API envelope、结构化错误映射和传输层抽象。
- 调度与执行模型现在携带任务预算、截止时间、耗时估计、质量目标、抢占与恢复模式、
  slice 结果、队列信息、指纹、诊断、检查点引用、incumbent 引用、精确整数目标值
  以及 proof/status 语义。
- 新增 portable checkpoint v2 模型和编解码器，支持模型指纹、SHA-256 完整性校验、
  incumbent/冲突/Benders 状态，以及对已识别 legacy v1 快照的显式迁移。
- remote 报告映射和 slice 编排会保留检查点状态及新增调度/结果字段。远端未知枚举值
  会被保守映射，不会被当作成功证明或成功终止。

## 测试与验证

- 新增函数符号专用契约覆盖，以及通用注册和回归测试。
- 新增 analysis fixture、协议、session、活动性、冲突、扰动、目标、报告、建议和能力
  测试。
- 新增使用同一组可人工核算模型的 SCIP 与 Gurobi 关键约束分析集成测试。
- 扩展 remote solver HTTP 测试，覆盖能力、调度、检查点、精确目标值、状态、诊断和
  兼容性 fixture。
- 同步更新 example 与 framework 测试，以适配函数符号和协议行为。

## 构建与依赖更新

- Kotlin 升级到 2.4.20，主构建的 JVM 和 Java 编译目标设置为 JDK 25。
- 文档中的基线环境更新为 JDK 25+，同时保留现有 JDK 8+ 兼容/打包分支的要求说明。
- Maven Compiler Plugin 升级到 3.14.1；Surefire 和 Failsafe 升级到 3.6.0。
- kotlinx 依赖对齐到 datetime 0.8.0、coroutines 1.11.0 和 serialization 1.11.0。
- Log4j 升级到 2.26.1，Log4j API Kotlin 升级到 1.5.0，SLF4J API 升级到
  2.0.19，Jackson 升级到 2.22.2，Ktorm 升级到 4.2.1。
- 多模块 Maven 构建中的版本号由 1.1.0 统一更新为 1.1.1。

## 迁移说明

- 下游 Maven 依赖请更新到 1.1.1。
- 使用 analysis API 时，应先检查返回的分析状态和证据，再应用修正；Unknown 和
  Unsupported 都是有意保留的结果。
- 使用检查点或调度任务前，remote solver 服务应先声明其支持的协议版本和模型能力。
- 更完整的 1.0.x 到 1.1.0 API 迁移说明请参阅 [1.1.0 changelog](1.1.0.md)。
